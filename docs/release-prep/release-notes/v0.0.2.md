# v0.0.2 — first test pre-release

> **This is the first release and a TEST release.** It is published as a
> GitHub **pre-release** (not stable) to prove the build → installer →
> release pipeline end to end. Expect rough edges; see Known limitations.
> **Windows only** (64-bit). See Requirements.

## Requirements

- **OS:** Windows 10/11, 64-bit (`windows/amd64`). No other OS is built or tested.
- **Runtime:** Microsoft Edge WebView2 (preinstalled on current Windows 10/11; the installer bundles the bootstrapper otherwise).
- **Install:** admin rights for the machine-wide installer, **or** use the portable zip (no admin).
- **Disk:** ~100 MB for the app + whatever you choose for the data root (any drive, e.g. `D:\ConductinoData` via `CONDUCTINO_DATA`).
- **AI features (chat, summarize, proposals):** bring your own key — one of `GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY` in `backend/.ai.env` (dev) or the app-data dir (installed). Without a key the library/reader work fully offline; AI turns report a clear “no key” error. Keys are never committed.
- **Build from source (optional):** Go 1.25+, Node 24, pnpm 9+, Wails CLI v2.15.0, NSIS 3 for the installer.

## What the app does today

**Library & reading**
- Pick a research folder → recursive library tree with locate-in-tree.
- Open `.txt` / `.md` / `.docx` / real text-layer PDFs as paginated documents; empty (0-byte) files open as blank pages, never errors.
- PDF canvas view with text layer; DOCX summaries you can write back to disk.
- Failures are typed (`unsupported`, `not_found`, `parse_error`, …) with honest toasts — no silent mock content.

**Summaries & AI workspace**
- Living summary documents on a paginated canvas: direct editing (blur-commit, Enter-split), highlights and saved notes.
- AI chat with tool use (read sources, propose edits), thinking/tool trace per turn, `@doc` targeting and region selection, one workspace thread per folder with SQLite-backed history.
- Change proposals (insert / modify / delete) that you accept, reject, or send back with an instruction — you gatekeep every change.
- One-click publish writes the summary through to a mapped `.docx`, then decorates in-file diffs you can review, accept/reject, or revise with full-document context.
- Summary mirrors keep AI working copies in sync when you edit or re-save underneath them.

**Providers & reliability**
- Three providers behind one boundary: Gemini (native) plus Groq and OpenRouter (OpenAI-compatible), with `AI_MODE` single/failover/auto and per-model fallbacks.
- Invalid-key errors abort with the exact variable to fix (no silent cross-provider quota burn); rate-limit text stays short and key-free in the UI, detail in the server log.

**Storage (new in this release)**
- One path resolver (`CONDUCTINO_DATA` → `.dev-data` → portable `./data` → `%AppData%\Conductino`); first run creates the data root.
- SQLite system of record: documents, changes, chat threads/messages, extract cache (200-entry LRU), remembered library folder.
- Installer offers a **directory page** (install to `D:` or anywhere); uninstall removes program files only, never your data.

## Known limitations

- Pre-release test build: no auto-update, **unsigned** (Windows SmartScreen will warn — choose “Run anyway” only for builds from this repo’s Releases page).
- Windows-only; low-spec friendly target (4 GB RAM / Celeron class) but not benchmarked per release.
- Scanned/image-only PDFs are a documented limitation (text-layer extraction only).
- AI web-search ranking in the browser panel is not connected (honest error, by design).

## Notes for testers

- Installer: `Conductino-amd64-installer.exe` — try the custom directory page (`D:\Programs\Conductino`).
- Portable: `Conductino-v0.0.2-windows-amd64-portable.zip` — unzip anywhere, no admin.
- Data directory: `set CONDUCTINO_DATA=D:\ConductinoData` before launch to keep data off `C:`.
- Smoke path: open folder → library tree → open pdf/docx → one tool-using chat turn → summary edit → publish → restart persists.
